# KB Creation Framework — v3.1.16

An operator-run, prompt-and-script framework for building auditable, practitioner-grade knowledge bases (KBs) — legal or company — with multi-model isolation, primary-source verification, mechanical lint gates, and a scored quality audit.

**Version:** 3.1.16 (patch — audit + cleanup), dated 2026-06-08
**License:** MIT, Copyright (c) Microsoft Corporation. See [`LICENSE`](LICENSE) and [`NOTICE.md`](NOTICE.md).

## What it is

The framework is a set of markdown prompts and PowerShell/Python scripts that a *host* (an agent harness such as GitHub Copilot CLI or OpenCode) executes. A **Lead** session runs the pipeline and dispatches builders, critics, fact-checkers and auditors on different model families. Nothing here is a service or library to install; the "program" is the prompt set plus the gate scripts.

Core idea: a claim only ships if it was generated by one model family, verified by another, grounded against a fetched primary source, and survived mechanical linting.

## The Six Rules

Defined in [`01-shared-axioms.md`](01-shared-axioms.md), which also carries later numbered rules (through Rule 20).

1. **Source-Constrained Specificity** — never request detail without naming the source type.
2. **Zero Tolerance for Fabrication** — verified or removed.
3. **Builder Isolation** — builders never see each other's output.
4. **No Self-Grading** — no model judges its own work.
5. **No Silent Skipping** — every phase runs; skips need explicit user approval.
6. **Model-Family Separation** — generation and verification use different model families.

## Pipeline

Phases run in this order. Each has a prompt under [`prompts/`](prompts/), and the machine-readable contract is [`audit-templates/phase-contracts.yaml`](audit-templates/phase-contracts.yaml).

| Phase | Purpose |
|---|---|
| 0.0 | Select and validate per-build model assignment |
| 0.1 / 0.2 | Scope the KB (audience, sources, density); pressure-test the scope |
| 1.1 – 1.3 | Independent research, merged topic list, per-topic drafting |
| 2.0 / 3.0 / 4.0 | Lead review, builder revision, draft comparison and single-source claim inventory |
| 5.1 – 5.5 | Fact-check: currency, citations, classification, single-source claims, operative mechanisms |
| 6.0 – 6.5 | Assembly, pressure test, Register-Lint + Verbatim-Linter, extraction of `practice/` and `authority/`, superset fact-check, A/B/C quality tiers |
| 7.0 | Final audit and Quality Scorecard |
| 8.0 / 8.5 | Cooperative and adversarial memo stress tests |

KB-type overrides for phases 5.1, 5.2, 5.3, 5.5 and 7.0 live in `prompts/legal/` and `prompts/company/`. Start a build from [`prompts/01-orchestrator.md`](prompts/01-orchestrator.md); the operator guide is [`HOW-TO-USE.md`](HOW-TO-USE.md).

## Output

Each KB is produced in three tiers: `full/`, `practice/` (interpretation stripped) and `authority/` (guidance and interpretation stripped), plus the required manifests and a Quality Scorecard.

## Repository layout

| Path | Contents |
|---|---|
| `01-…07-*.md` | Rulebooks: shared axioms, info-gather, builder, fact-checker, build and refresh orchestrators, audit system |
| `prompts/` | Phase prompts, with `legal/` and `company/` overrides |
| `*.ps1` (root) | Gate and utility scripts: `Verbatim-Linter`, `Register-Lint`, `Detect-Reattribution`, `Generate-QualityScorecard`, `Validate-*`, `Extract-*`, `Diff-KBVersions`, `Detect-CrossKBConflicts`, model-registry tooling |
| `audit-templates/` | Phase contracts, JSON schemas, quality dimensions, model presets and role profiles |
| `HOST-CONTRACT.md`, `hosts/` | Normative host requirements; per-host notes for Copilot CLI and OpenCode |
| `adapters/` | Optional components: `primary-source/` (eCFR, Federal Register, Congress.gov, GovInfo), `crawl4ai-fetch/` (grounding), `citation-engine/` (LlamaIndex), `evaluator/` (Inspect), `model-providers/` (Azure Foundry, Copilot CLI, Ollama, OpenRouter) |
| `specification/` | Technical specification, overview and LLM recreation prompt |
| `examples/` | Example registries, scorecard and audit reports |

Adapters are optional: no prompt hard-fails if one was not run.

## Requirements

- PowerShell 7 (`pwsh`) for the scripts.
- Python 3 for the adapter sidecars. Each adapter pins its own dependencies in its `requirements.txt`.
- A host that satisfies [`HOST-CONTRACT.md`](HOST-CONTRACT.md). Hosts below the full multi-agent level must document the consequence for model-family separation (Rule 19).
- Provider credentials as environment variables (for example an OpenRouter or Congress.gov/GovInfo key), only for the adapters you use.

## Known limits at this version

- Rule 19's wording (`5.4 ≠ 5.2`) disagrees with `phase-contracts.yaml` (`5.x ≠ 1.3`). It is logged as a follow-up and not fixed here.
- The LlamaIndex citation engine (v3.1.14) and Inspect evaluator (v3.1.15) were smoke-tested in fallback mode only. LLM-mode runs were not covered.
- `HOW-TO-USE.md` and the specification files still carry their v3.1.0 labels; the version-specific history is in the changelog.
- No non-US primary-source adapter is included; the primary-source adapters cover U.S. sources only.
